# Code Map: PRD/ERD vs. Current Implementation

This audits the repository against [`PRD.md`](PRD.md) and [`ERD.md`](ERD.md). Status values: **Implemented** (matches the doc and is wired up end-to-end), **Partial** (exists but incomplete or informally structured), **Missing** (no code).

## Architecture

Two layers now work together:

1. **Graph pipeline** (`pipelines/merge_graph.py`, `normalize_graph.py`, `extract_subject_index.py`, `components/graph_loader.py`, `filters.py`, `visualizations.py`) — reads `json_nodes/<subject>/*.json`, merges into `data/graphs/merged_graph.json`, and serves the graph/flashcard pages (`pages/0`–`6`).
2. **`core/` package library** (`store.py`, `registry.py`, `packages.py`, `mcq_parser.py`, `pdf_extract.py`, `grading.py`, `attempts.py`, `learning_links.py`) — the ERD's question-authoring, delivery, grading, and remediation model. Wired into the app via `pages/7_Author_Packages.py`, `pages/8_PDF_Drafts.py`, `pages/9_Take_Test.py`, `pages/10_Review_Results.py`, plus `pipelines/build_registry.py` and `pipelines/check_quality.py`.

The two layers share data through `core/learning_links.py` (resolves a question's `node_links` back to graph node definitions/neighbors/flashcards) and `core/registry.py` (builds `data/registry/registry.json` from both `json_nodes/` and the graph's subject metadata, so package authoring reuses the same subject list as the graph).

## Non-functional requirements

- **Python 3.10+, UTF-8**: consistent across `core/` and pipelines.
- **Atomic writes / no silent corruption**: `core/store.py.write_json()` does tmp-file + `os.replace`. Legacy pipelines (`normalize_graph.py`, `extract_subject_index.py`) still write directly with `Path.write_text()`, no atomicity — narrower blast radius since they're simple overwrites, but inconsistent with the NFR.
- **Published packages immutable**: implemented and exercised by the seed package at `database/introduction_to_optimization/optimization_basics_quiz/`.
- **PDF cleanup**: `core/pdf_extract.py.open_pdf()` closes the document in a `finally` block; now actually invoked from `pages/8_PDF_Drafts.py`.
- **Automated tests**: `tests/` covers `attempts`, `grading`, `mcq_parser`, `packages`, `pdf_extract` (21 tests, all passing).

## Remaining gaps

The structural gaps are narrower than a first read of `core/` alone suggested:

- **Node identity**: still free-text keyed, no canonical ID/UUID — the ERD's top risk item is unresolved.
- **Graph build history**: no `GRAPH_BUILD`/`NODE_SNAPSHOT` — each `merge_graph.py` run overwrites the graph in place.
- **User accounts**: `USER` stays a display-name string, matching the ERD's stated MVP scope but not a real identity.
- **Join-table integrity**: subject/source/node relationships are denormalized onto the node/registry JSON rather than being separate ID-linked records.

These four align with `ERD.md`'s own "Risks and Decisions" and "Recommended Migration Order" — they're the deferred-by-design items for a later migration phase, not accidental omissions.
